## A. One booking-display owner; no extra customer journey

**Design intent:** give a useful Home primary action in either state, while retaining the common booking system's existing controls.

**Implementation specification:**

1. Home initial markup is safe OFF: href=/contact, label Arrange a visit, phone icon. Use data-home-appointment-entry only on this anchor, not its surrounding action group. The header retains its existing Book wording, short phone label and accessible name.
2. The Home entry contains a label span with data-booking-on/off, two decorative spans with class=appointment-icon and data-home-entry-icon=phone/calendar, and the existing arrow. Both icon spans are aria-hidden; their hidden attributes switch phone/calendar so inactive decoration occupies no space. The narrow .hero .appointment-icon[hidden]{display:none} rule must win even if an existing icon class sets display:grid. No innerHTML rebuild on each refresh.
3. site.js reuses productState.getSnapshot().enabled, exactly as the existing site does. It never sets the product state. The helper synchronizes href, accessible name/title, icon visibility and the label synchronously before the generic guard pass. Set attributes/text only when values differ. The shared label binding remains an idempotent co-consumer of that same state; it cannot erase icons.
4. The generic pass skips only the two actual entry elements. The header helper retains its aria-current behavior on /booking. No generic selector removes booking-only from other links/forms. H2, dialogs, menu/footer booking links and generated topic/doctor booking links keep their current guards.
5. ON means the action may open the existing route. It does **not** certify availability or payment/staff/email readiness. Existing admissionAllowed, foreground freshness, route guard and submission checks remain authoritative. A refresh that retains an enabled display retains its normal label; no new disabled/loading policy is invented for this presentation change.
6. ON→OFF changes the visible Home action to Contact and leaves the other three actions usable. Do not create a second form, call flow or draft store. No new network request, timer, event collection or provider action is added.
7. Responsive ON styling reads the existing documentElement data-booking-state. Do not copy the private body[data-preview-booking] control into runtime or create another availability state. Below480px, ON first-row buttons stack. OFF first-row buttons stack below390px. All labels may wrap at increased text size; nominal one-line fit is not a white-space:nowrap requirement.
8. Browser click dispatch is single-threaded; one synchronous sync completes label/destination changes before another ordinary input event. Do not add a custom click-to-book handler that competes with current navigation. Route-level admission remains the final authority if state becomes stale afterward.

Review initial OFF/unknown, ON, retained-ON checking, confirmed OFF, failed refresh, state changes on Home and a subsequent route entry. Repeated unchanged refreshes must not replace nodes, remove focus, erase icons or restart H1. These are future runtime observations, not claims made by the label-only study.

## B. Motion lifecycle and focus

**Design intent:** implement only the requested calmer care entrance, and let each newly stacked About doctor keep its original sequence when reached.

### Home H3-card

- In supporting(), keep the H3 parent heading-only branch. A child owns exactly its own .care-card; add one opacity0→1 track,0–480ms, cubic-bezier(.23,1,.32,1). No transform track on card, .care-media, .care-object or img. Do not add a CSS entrance, forced group stagger or new loop.
- Set c.media=[] before prepare. All actual image dimensions/srcset and lazy attributes remain. A late/failed image can use the existing media-failed treatment; it cannot keep the card's text invisible. No timeout is required because essential reading no longer waits on that promise.
- In motion.sync(), add the narrow H3-card focus condition before the existing readiness-dependent form logic: if the card contains document.activeElement and is unfinished, finish that card. Do not require ready or visible for that focus branch; finish() does not restart preparation. Subsequent async readiness may allow the already-finished card to remain done, never reset it to0.
- Retain current independent sentinel behavior, native reduced movement, Home progress preservation, hidden-tab pause, re-entry-complete behavior and cleanup restoring the original style attribute. An animation construction failure follows the engine's existing restore-and-show path; do not add CSS opacity0 that survives engine failure.
- Private replay uses exactly480ms with no60ms example stagger. It decodes images first only to judge appearance; runtime deliberately does not gate copy on that decode. The static study does not reproduce the engine's individual viewport admission.

### About A3-panel

- children() always registers A3:.doctor-card-about, alongside existing selectors. Preserve IDs A3/0 and A3/1 using the unfiltered canonical order. Do not add data-section-scene to child rows or create duplicate top-level scenes. Existing diagnostic play/seek/settle/unmount behavior must continue to find parent and children.
- Add an early parent-A3 heading-only return, like H4: stage=.section-heading, media=[]. The remaining A3-panel branch retains original2300ms desktop/1900ms phone symbol/fact tracks and12000ms glint. Its native initial/photo/name body is not animated or hidden as a new entrance.
- Child stage is its identity group, explicitly c.stage=card.querySelector('.about-doctor-identity')||card; c.media=[]. This puts the existing visibility sentinel on the doctor introduction even if a future portrait renderer contains its own composition. Native photo loading stays parallel and cannot gate the symbol/fact clock.
- In flushLayout(), preserve state for homeScene(s) **or s.type==='A3-panel'**, before the generic finish-all non-Home branch. Reuse snapshot/build({state}) and existing stable IDs; normalize progress if the desktop/phone duration changes. An unstarted second row remains time0/unstarted, a half-played row keeps its fraction, a completed row stays complete and its idle loop phase survives. Do not change A2, T2/T3 or other non-Home resize policies.
- Re-measure glint bounds through the existing card/root resize owner. Reserved portrait dimensions prevent decode from moving the identity. A font swap can move an icon internally even without changing the card's outer size: when document.fonts is available, its ready promise and loadingdone event queue the two A3-panel roots through the existing layoutPending/queueLayout owner. Guard the promise with disposed and register the event through the existing listen()/dispose mechanism. Existing120ms coalescing prevents duplicate rebuilds; normalized-state preservation above prevents a late font from finishing the unseen doctor. No new perpetual observer or loop.
- Ordinary first entry waits for its own sentinel. Browser Back/Forward scroll restoration intentionally settles existing scenes; preserve that behavior. Route exit/dispose cancels owned tracks/glints/listeners and stale work through existing generation checks. No former doctor's glint survives on the next page.

## C. Layout, exact copy and media contracts

**Treatments alignment:** at≥768px, .treatment-overview uses grid-template-rows:auto 1fr and row-gap:0. Each .treatment-overview-group spans both rows and uses grid-template-rows:subgrid. The header occupies row1 and the five-row topic list row2. Column gap remains28px/its existing tablet value. Body list retains its five equal tracks and24px bottom padding. Phone retains the normal stacked flex/grid rules. Put this enhancement under @supports; a browser without subgrid keeps the current readable equal outer columns, without a script or clipped fixed-height heading. Alignment is required in supported current browsers, not silently claimed for the fallback.

**Heading semantics:** overview-title-physician and overview-title-women are unique h2 IDs; the downstream #physician/#women IDs remain the actual destination sections. No row acquires data-topic merely for styling: that attribute belongs to explorer selection controls. Insets/outline/padding must not clip text or the header focus ring.

**About copy:** retain the exact two proposed introductions,35 and33words respectively. Use existing educationText, since and source-backed care wording; no unconfirmed personality/experience promise. A smaller numeric word target is not permission to remove a fact. Keep every existing qualification, institution, fee and at-clinic statement. A source fee/year change must update every corresponding renderer; “both”/“either” wording may be used only when both canonical values agree. Distinct values must be shown per doctor rather than choosing the first doctor's value silently.

**Shared facts:** clinic-glance.js accepts prepared canonical entries and escapes text; it does not parse comma positions or fetch facts. Home and About can use different short labels around the same values. Keep the already-visible location and concerns useful without repeating a long biography. Explicit short locality, if needed, belongs beside address in model.mjs. New shared CSS imports once after relevant existing base styles. Page-specific changes stay in their current owner.

**Portrait geometry:** retain300×375px desktop,220×275px tablet,100×125px phone,88×110px below360. Until genuine portraits exist, use SG/PG and the established medical identity in that area. The private neutral variant uses a single blue/mint surface, existing icon, Lora78px initials (32px phone) and16px clinic name (duplicate brand omitted on phones). No false person's face, fake signature or extra verification mark. Photo-placement mode is private only and has the identical measured section/card geometry.

**Future genuine image:** use one approved local portrait per doctor with width/height reserved; actual crop may be tuned when supplied. A native img error reveals the same name/initials area without collapsing the layout. It does not fetch a substitute person. This future asset replacement is not a reason to block implementing the approved neutral composition now.

**A32 overlay:** limit preparation-art.mjs dispatch to A32 report/list/note; return empty markup for every other composition/layer. Explicit .preparation-note-content text/path styles avoid changing unrelated svg text. SVG words/checks remain decorative, non-interactive and inherit the paper's transforms. Source coordinate boxes, report/list/note stack and responsive assets remain byte-identical. No overlay positioning against page pixels; no mix-blend/filter used to disguise misalignment. The actual17px preparation content remains the useful reading source.

**Responsive reading:** widths1200/1199,768/767,480/479,390/389 and360/359 are explicit boundaries to inspect, plus1920,1440,1024 and320. A target height is measured at normal text size, not imposed after text grows. No ellipsis, clipped description, tiny replacement font or nowrap-only action label. At larger text sizes, natural wrapping/stacking takes priority over keeping one desktop line. The phone identity uses natural flow and may break an unfit name rather than overflow. Review actual browser zoom separately from private text-stress injections.

About care links use grid-template-columns:30px minmax(0,1fr) minmax(16px,max-content), with the specified8px gap (7px on phones). The arrow keeps its own natural width under text enlargement instead of overflowing a fixed16px track; concern text wraps in the middle track. Keep the arrow and icon, rather than hiding them to make a size observation pass.

## Primary references checked for this pass

- [MDN: subgrid](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Grid_layout/Subgrid) and [card layout](https://developer.mozilla.org/en-US/docs/Web/CSS/How_to/Layout_cookbook/Card): shared row tracks can align neighboring cards without a script. Viewport resizing or a private font-size injection is not by itself full conformance proof.
- [MDN: Element.animate](https://developer.mozilla.org/en-US/docs/Web/API/Element/animate) and [using Web Animations](https://developer.mozilla.org/en-US/docs/Web/API/Web_Animations_API/Using_the_Web_Animations_API): retain explicit ownership of animation objects, fills and cleanup; do not leave a decorative animation responsible for permanent access to text.
